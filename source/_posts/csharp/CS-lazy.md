> C#知识补充之Lazy类

<!-- more -->

## Lazy类是什么

`System.Lazy<T>`是一种延迟创建类的方式 相当于一种懒标记，只有你第一次使用这个类的时候才会真正的去new

假设有一个类Foo 
`new Lazy<T>()`括号内可以填初始化函数或lamda类 函数要有返回值为T
```csharp
var lazy = new Lazy<Foo>(() =>
{
    return new Foo();
});
Foo f = lazy.Value;      // 此处才 new
bool made = lazy.IsValueCreated;
```

## Lazy能解决什么问题

`Lazy`可以总结为一句话 用时创建 只建一次 线程安全

- 用时创建：`lazy`相当于标记了需要创建，不需要真正的创建一个类，当你不确定某些超级大的类要不要创建时 可以用这个来标记 减少不必要的开销
- 只建一次：对于像单例模式这样的类 我们可以用`lazy`来构建，而不是判断是否存在在new
- 线程安全：`lazy`能保证在多线程中创建时只有第一个线程才能执行构造函数 并且把这个创建的对象分给其余线程

- 缺点：`lazy<T>` 只保证"初始化 + 发布"这一步的线程安全，不把 T 变成线程安全类型。对象创建之后被多线程并发访问时，仍需自己加锁


## 语法

构造函数
| 名称 | 说明 |
| --- | --- |
| `Lazy<T>()` | 初始化 `Lazy<T>` 类的新实例。发生延迟初始化时，将使用目标类型的无参数构造函数|
| `Lazy<T>(Boolean)` | 初始化 `Lazy<T>` 类的新实例。发生延迟初始化时，将使用目标类型的无参数构造函数和指定的初始化模式|
| `Lazy<T>(Func<T>, Boolean)` | 初始化 `Lazy<T>` 类的新实例。发生延迟初始化时，将使用指定的初始化函数和初始化模式| 
| `Lazy<T>(Func<T>, LazyThreadSafetyMode)` | 初始化使用指定初始化函数和线程安全模式的 `Lazy<T>` 类的新实例| 
| `Lazy<T>(Func<T>)` | 初始化 `Lazy<T>` 类的新实例。 发生延迟初始化时，将使用指定的初始化函数| 
| `Lazy<T>(LazyThreadSafetyMode)` | 初始化类的新实例，该实例`Lazy<T>`使用无参数构造函数 T 和指定的线程安全模式| 
| `Lazy<T>(T)` | 初始化使用预初始化指定值的类的新实例`Lazy<T>`| 

属性
| 名称 | 说明 |
| --- | --- |
| `IsValueCreated` | 获取一个bool值，该值指示是否已为此 `Lazy<T>` 实例创建值。|
| `Value` | 获取当前 `Lazy<T>` 实例的延迟初始化值。 |
	
LazyThreadSafetyMode
| 名称 | 说明 |
| --- | --- |
| `ExecutionAndPublication` | 完全线程安全;使用锁定来确保只有一个线程初始化该值。推荐使用 |
| `None` | 不是线程安全 |
| `PublicationOnly` | 完全线程安全;线程争用来初始化值。 |

## 能用来做什么

- 线程安全的单例模式
- 延迟加载大对象 / 大缓存内容
- 昂贵依赖 / 资源延迟初始化  如：数据库连接、配置解析、复杂计算结果、第三方 SDK 初始化
- 互相引用的对象 用来避免死锁
